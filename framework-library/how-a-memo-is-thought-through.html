Investment Analyst Analysis-and-Judgement Memo — THINKING SOP

Status: LIVE V1, 13-May-26 Owner: Investment Analyst role (Watson) Parent: 01-SYSTEM-OVERVIEW.md Weight: 10× the Communicating SOP and 100× the Presenting SOP. Spend time accordingly.

Standing instruction

Every minimum in this SOP is a MINIMUM, never a maximum — full rule: 01-SYSTEM-OVERVIEW.md, "Standing instruction", the single statement. Skirting an important topic to hit a number is failure.

How to use this SOP

Three stage-specific linear procedures live in this SOP — one for Triaging, one for Early-Stage Assessment, one for Deep Dive. When Watson sits down to write a memo, Watson opens the procedure for the relevant stage and walks it top to bottom. Each numbered step tells Watson exactly what to write, at what depth, with what minimum bullet count.

The three procedures are cumulative deltas: - The Triaging procedure starts from the canonical V4.3 skeleton (memory/skills/investment-analyst/aj-memo/skeletons/TRIAGING-skeleton.md): copy it into Files/{TICKER}/Triaging/, rename to the memo filename, then fill in every {…} placeholder by walking the procedure below. It is not written from a blank file. - The Early-Stage Assessment procedure says "carry forward everything the Triaging memo produced, unchanged, then add these deltas". - The Deep Dive procedure says "carry forward everything the Early-Stage Assessment memo produced, unchanged, then add these deltas".

Watson does NOT rewrite from scratch at each stage. The prior memo is preserved.

MANDATORY — start from the skeleton, finish through the gate [added 2026-06-12]

Two structural guarantees make the memo right-by-construction, so a simple brief ("write the {TICKER} Triaging A&J memo to a very high standard") reliably yields a compliant memo:

  1. Start from the canonical skeleton. Copy skeletons/TRIAGING-skeleton.md (ESA/Deep-Dive skeletons follow the same shape with their added Sections). The skeleton already carries the exact required structure: Section A — Summary Snapshot (R3 fields only), Section B Executive Summary B.1–B.6 in full, the six Master-Rating headings, Section C Pillar I/II with blockquote summaries and inline [A]–[F] grade slots, Section D (Pillar III — note-only at Triaging), Section E, Section F, and a reminder to author the paired Go-No-Go Checks one-pager. Do not delete any heading; fill them in.

  2. The QC gate now enforces the structure. generate_qc_audit.py (run in Phase 4, per 05-IA-EXECUTION-DISCIPLINE.md §6) HARD-fails — and blocks close-out — on a missing/non-canonical Section A heading, any missing B.1–B.6 subsection, fewer than six MR headings, any major Section lacking a > blockquote summary, a banned **JUDGEMENT SUMMARY label, or an absent paired Go-No-Go file. A memo built on the old skeleton, or one that stops at B.3, cannot pass. Run the script in-loop until it returns exit 0 before declaring the memo done.

Required Attributes and Core Questions — the lift from the old framework

Every Element in Pillar I and Pillar II carries a set of Required Attributes (containers) and Core Questions (the specific analytical questions Watson answers). These were lifted from the old framework's pillar-tree-canonical.json into the new framework's Elements, mapping by content. Full list of all 60 Required Attributes and 170 Core Questions: projects/SA - IA A&J Memo Batching Automation/folded-projects/SA - Investment Analyst A&J memos/briefing/04-elements-with-RAs-and-CQs-integrated.md.

In every Element section of every memo, Watson writes: 1. A short opening synthesis bullet — the Element's headline finding 2. For each Required Attribute in the Element: a Required Attribute summary block (minimum bullet count per the pass-depth floor and any multipliers) PLUS each Core Question inside it answered at minimum bullet count per the floor and multipliers 3. A grade on every judgement-bearing Core Question [D-AJ-21, 16-Jun-26]. Any Core Question that asks for an assessment or a verdict carries an inline [A]–[F] grade in its label, e.g. RA1 CQ1 — Strong external change forces? [D]. A purely factual or descriptive Core Question (one that reports a number or a fact with no judgement) is left ungraded but TAGGED [factual] in its label so the QC gate can tell an intended-ungraded question from a missed grade. A judgement-bearing Core Question with no grade is a HARD QC fail. This Core-Question grade is IN ADDITION to the existing Element and Required-Attribute grades, which are unchanged. Applies to all three stages (Triaging, Early-Stage Assessment, Deep Dive). v2 answer-lines [D-AJ-24, 16-Jun-26]: each Core Question's MAIN bullet carries a one-line ANSWER (the verdict) before its evidence sub-bullets, and each Required Attribute leads its body with a one-line ANSWER bullet; the same verdict is also carried in the Element's one consolidated judgement-summary box. The verdict appearing twice (in the summary box and at the RA/CQ) is intentional.

Standing refinements (locked 02-Jun-26, from the Elekta Early-Stage Assessment A/B test) — apply in every procedure

These are checklist / discipline refinements. They do NOT change the Elements, Pillars, multipliers, depths or floors.

Grade-discipline calibration (D-IA-4RR-11) — the "tighter grade discipline"

Before finalising any A-F grade on any Element, Required Attribute or Core Question, run this calibration step:

  1. Name the comparison set. State the set the grade is struck against: the live cohort peers whose reports are on disk, or, where no cohort exists, the named sector-peer set or an explicit universe base rate. A grade with no named comparison set is not finished.
  2. Place the stock in the set. State where the stock ranks within that set (top, upper-half, median, lower-half, bottom).
  3. Apply the bell-curve definitions from the canonical Viewforth scale stated once in memory/context/CLAUDE-CANONICAL.md (loads every session). Grades are relative percentiles of the named comparison set, not absolute scores. (Corrected 31-Jul-26: this line previously misstated the B, D and F bands.)
  4. Apply the validation-horizon and mediocrity-shunning lens at Early-Stage Assessment already for the management-quality, business-quality, case-predictability and driver-trackability Elements (E9, E10, E11, E12, E18, E19). Do not defer the strict lens to Deep Dive. An Early-Stage Assessment quality grade that runs half a notch generous pre-judges the Deep Dive mediocrity-shunning gate, which parks C/D/F on exactly these dimensions.
  5. Write the one-line justification. Every Element grade carries one line in this form: "[B] vs cohort because X; held off A by Y; held off C by Z." This forces the grade to be defended against both the notch above and the notch below.
  6. Sanity-check the roll-up. The Element headline grade must sit within ~1 notch of the mean of its own Required-Attribute and Core-Question sub-grades. A headline more than one notch above the weighted sub-grades is grade inflation; either re-justify it explicitly or lower it. The Quality Control Audit script flags this automatically.

Source: the Elekta Early-Stage Assessment A/B test (02-Jun-26) found the new memo's grades ran about half a notch generous versus the disciplined 14-May baseline, sharpest on E9 operator [B] versus baseline [C], where the [B] headline sat above the weighted sub-ratings.

Specifics-retention sweep when consolidating from the 4 reports (D-IA-4RR-13)

Consolidating four long family reports into one memo loses hard, high-salience datapoints in the compression. Before close-out, sweep the four source reports for high-salience specifics and confirm each material one has carried into the memo: named survey percentages, specific broker price targets with the broker names, specific invalidation thresholds and trigger levels, named management quotes, and hard financial datapoints (margins, returns, leverage, growth rates with their period). Where a material specific did not carry, add it.

Source: the Elekta Early-Stage Assessment A/B test dropped 5 hard specifics the baseline carried (a 76% Unity-rejection survey datum; broker bear targets ~SEK39 and ~SEK35-36 with names; an R&D-capitalisation earnings-quality nuance; and others).

When no prior-stage memo exists in the new structure (D-IA-4RR-15)

The procedures are cumulative deltas over the prior-stage memo. When NO prior-stage memo exists in the 4-report structure to carry forward (for example, the first Early-Stage Assessment or Deep Dive built under the new structure, with only a legacy-era prior memo or none at all), do NOT treat the absent carry-forward as a licence to write thin. Build the full stage memo at that stage's depth from scratch, every in-scope Element at its stage floor, exactly as if the prior-stage content had been carried forward. The cumulative-delta discipline is a labour-saving device, never a depth-reduction.

Floor-enforcement sync note (D-IA-4RR-16)

The per-Element, per-Required-Attribute and per-Core-Question bullet floors stated in Procedures 1, 2 and 3 (with the ×2 / ×4 multipliers) are now ENFORCED at Early-Stage Assessment and Deep Dive by scripts/generate_qc_audit.py, not merely stated here. The script holds a mirror copy of these floors in ELEMENT_BULLET_FLOOR, RA_FLOOR_OVERRIDE and CARVE_OUT_ELEVATED. If any floor in these procedures changes, update the script's floors tables in the same change. The script carries the reciprocal maintenance note.

PROCEDURE 1 — TRIAGING memo (Stage III, first A&J pass)

Stage purpose. Lightly triage the case's attractiveness. First A&J pass through the funnel. Light depth across in-scope Elements.

Stage qualitative test (NOT rated; alignment language). Does the case have large amounts of positive change forces?

Decision pivot at end of memo. Progress to Early-Stage Assessment, or park.

PARK IS A VERDICT, NOT A GATE ON PUBLICATION (Richard's ruling, 03-Aug-26). A memo that recommends park is published exactly like one that recommends progress. The recommendation is CONTENT; it never decides whether the memo is released. A parked case is frequently the more valuable document: it is the written record of why Viewforth is not spending further money or research hours on the name, and it carries the reassessment criteria that say what would change the answer. The only gate on publication is quality: zero HARD FAILs on the Quality Control Audit and no unresolved judge escalation. Full rule: 05-IA-EXECUTION-DISCIPLINE.md §7d. The same paragraph forbids the memo pipeline reusing the word "park" for a mechanism failure.

Approximate memo length floor. ~9,000 words minimum (excluding Section A and Section F). The Investment Analyst writes more when the analysis warrants.

Cohort-relative grading (D-IA-4RR-09). If the stock is in an active cohort, strike every A-F grade in this memo against the live cohort peers (whose Change Forces reports are on disk), not against an abstract universe base rate, even at the default cohort dial. Universe-anchored grading floats grades upward and loses decision-useful sharpness. Anchor each grade explicitly. See 06-RESEARCH-SOURCE-MAP.md section 4b.

Step 1 — Section B Executive Summary (page-level BLUF) — third pass

Write the page-level Bottom Line Up Front at the top of Section B. Three to five judgement bullets immediately after the title. Each captures one element of the case. No data, no hedging, no padding.

Master Ratings fold in here as part of the BLUF opening. The six Master Ratings get a short summary line each (first pass — light at Triaging) — e.g.:

Master Ratings (first pass — light at Triaging): - Technical momentum: [grade] — [one-sentence rationale] - Sell-side earnings momentum: [grade] — [one-sentence rationale] - Thematic fit: [grade] — [one-sentence rationale] - Pillar I Case change elements: [grade] — [one-sentence rationale] - Pillar II Case building blocks: [grade] — [one-sentence rationale] - Pillar III Investment case components: not applicable at this stage

Master Ratings are loosely-derived qualitative summaries. They are informed by underlying ratings but the Investment Analyst retains discretion to weight and override.

Section B target length at Triaging: ~700 words minimum.

RA8 WAS TIGHTENED ON 17-Aug-26 (Richard's ruling). Read its full definition in the canonical elements briefing before grading it — it is no longer a one-line placeholder.

The correction in one line: a false friend is defined by OPACITY of the transmission mechanism from company actions to earnings per share, not by the case being bad. A weak business, a deteriorating business, or a cheap multiple attached to falling margins is not a false friend if the path from action to earnings is traceable. Those findings are real and must be routed to the Element that owns them (accounting, cash conversion and cheap-but-deteriorating go to E1 RA2 Robust base; margin or volume decay from competitive forces goes to E11; too many moving parts goes to E7), never suppressed and never left driving this grade.

A Risks report's competing-hypotheses matrix naming "false friend" is an INPUT, not a verdict. It tests Richard's own three-profile framework, so it is a second reading of the same idea, not a second witness. State what its finding actually rests on, reach your own view on the opacity test, and say whether you agree.

Why this changed, measured not assumed: across 157 memos the guardrail graded D or F on 71.3% of stocks and A or B on 4.5%; of 100 D/F blocks read, between 6% and 25% applied the opacity test (6% strictly, 25% on a deliberately over-inclusive reading, so at best three quarters rest on something else), while 72% deferred to the Risks report. Root cause: the canonical briefing defined this Required Attribute as TBD (placeholder in old source) — the writer had no test to apply. Evidence and full reasoning: projects/SA - IA A&J Memo Batching Automation/SESSION-RECORD-2026-08-17c-...md §7.

Replaces and extends the prior Pre-flight item 1 "Cohort check" with the full D-BATCH-25 rule.

Why this rule exists for the IA role. The IA's analytical edge is judgement, and judgement is sharper when calibrated against a comparable set. Reading peer A&J memos surfaces what other reasonable analyses concluded about similar businesses; reading peer research reports surfaces the cross-fertilisable structural information (business model, sector dynamics, regulatory environment) that the IA should weight before making a Stock X judgement. Five-year evidence per UWB-6: picking the right thematic dominates picking the right stock; cohort and sector peers carry the load-bearing thematic information.

Difference from the Researcher's version of the rule. The IA's peer channel carries BOTH the peer's research-derived content (via the master-digest, which synthesises the peer's family reports) AND the peer's prior A&J judgement (via its ratings.json grades, and any prior comparison-judgements the master-digest records); the Researcher works only from peer research reports (there is typically no prior memo when a research report is authored). The IA still asks the same questions of the peer set: how the cohort was previously rated, what comparison-judgements were made, what counter-factuals were considered.

Four guardrails — same as the Researcher rule, scoped for IA.

Dial modulation (D-IA-4RR-02). The cohort and sector integration dials (set at brief intake, default "normal"; see 06-RESEARCH-SOURCE-MAP.md section 3) modulate this injection: "lot" widens the peer set and leans harder on cohort/sector base-rates when grading; "little" treats the stock as idiosyncratic and minimises peer weighting. "Normal" is the behaviour described below.

  1. Staleness gate — D-BATCH-17 three-tier rule. Peer memos and reports older than the threshold do NOT auto-inject. Change-sensitive content skipped if older than 2 months; other content skipped if older than 6 months. The IA notes in the memo's Section F Appendices any peer content that exists but was too stale to inject.

  2. Relevance gate — the IA's LLM prompt explicitly instructs: "Integrate peer context ONLY where directly relevant to Stock X's analysis or to a comparison judgement. Do not blur Stock X's specifics with peer specifics. Flag where peer judgement conflicts with Stock X's observed facts. Quote Stock X's own facts when peer context could overwrite them. When the cohort base rate matters for a grade or rating, state the cohort base rate and grade Stock X against it."

  3. Built-in economy (replaces the old 50,000-token budget and summary-of-summaries). The peer channel is already compact: one grade-free master-digest per peer, of which the writer reads only the SNAPSHOT + NET READ slice by default. There is no per-memo peer token budget to police and no summary-of-summaries cache to build — the master-digests are pre-built once per peer (out of the memo loop) and reused. The writer opens a full peer digest only to drill a specific comparison it is actually making.

  4. Audit logging — the peer set the writer received is recorded in the sidecar peer_injection (each peer, whether its master-digest and ratings.json were present, and the cold-start backfill_needed list). This replaces the old per-injection audit record of peer-memo/report token counts and summary-of-summaries usage (D-BATCH-23).

Cohort context presented first, sector context second (same as Researcher rule). Cohort peers have higher relevance than sector peers. The IA's prompt orders cohort context first, sector context second; peer_resolver.py selects cohort peers first, then sector (then the broad industry only if the pool is short).

What the writer receives per peer (the peer channel; assembled automatically at Station 1 by peer_resolver.py).

For each cohort peer (then each sector peer, cohort-first): 1. The peer's master-digest (Files/{PEER}/master-digest.md) — one grade-free qualitative synthesis of that peer's family research (Change Forces, Business Foundation, and at deeper stages Leadership and Risks), built once per peer and reused. The writer reads its SNAPSHOT + NET READ slice by default. 2. The peer's ratings.json — the peer's A-F grades (the canonical grade source; the master-digest is deliberately grade-free). 3. Cold-start (no master-digest yet): use the peer's ratings.json plus the universe base rate, and flag the cold-start in Section F. The backfill list is in the sidecar peer_injection.backfill_needed.

The writer does NOT itself go and read peer A&J memos or a peer's raw four-report family — the master-digests carry the cross-fertilisable content, and peer_resolver.py selects the peer set (cohort first, then sector, extending to the broad industry only if the pool is short).

What the IA does with the injected context.

  • Calibrate grades. When grading Stock X on a Required Attribute (A-F bell curve), state the cohort base rate explicitly and grade Stock X against it. Example: "Capital efficiency: cohort base rate is C across the four Nordic facilities-services peers (Caverion B+, Coor C, ISS C-, Bravida A-). Bravida grades A on capital efficiency against the cohort base rate; the regulatory-mandated electrical-work segment generates significantly higher returns on tangible capital than the discretionary services peers."
  • Apply the J-then-A-then-I order at cohort scope. Lead with the comparative judgement, then the analysis behind it, then the supporting peer-level information.
  • Cite the peer channel explicitly. Format: [per CAV-FI master-digest] for a qualitative read-across, or [per CAV-FI ratings.json, E9 = B] when citing a peer's grade (peer-grade citations are cross-checked deterministically against the peer's ratings.json).
  • Surface cohort-level conflicts. When the IA's Stock X analysis conflicts with the prior cohort-level pattern, name the conflict in Section C (Pillar II) and resolve it explicitly: which view wins, why, what new evidence Stock X provides.
  • Use cohort context to inform conviction qualifier. When the cohort is well-covered and consistent, conviction can be higher because the comparative frame is sharper. When the cohort is sparse or inconsistent, conviction qualifier should reflect that.

Where the rule reads cohort and sector definitions from (same as Researcher rule).

  • Cohort membership: databases/data/cohorts-v3.json (canonical cohort definitions v3; 972 tickers, Third Pass, full 15-zone framework; integrated 26-May-26; supersedes cohorts-v2.json 336 tickers).
  • Sector membership: databases/data/universe.json (Viewforth taxonomy: Industry BROAD, Sector NARROW; INVERSE of GICS per reference memory entry reference_viewforth_taxonomy.md).
  • The peer channel itself: each peer's Files/{PEER}/master-digest.md (grade-free qualitative synthesis) and Files/{PEER}/A-J-memo/ratings.json (the peer's grades), resolved by peer_resolver.py. Each master-digest is built once per peer, out of the memo loop, from that peer's four family folders (41-change-forces|42-business-foundations|43-leadership-foundations|44-risks).

Pre-flight integration. The Pre-flight section above (item 1 Cohort check) is now replaced by this full D-BATCH-25 rule. The IA reads cohorts-v3.json and universe.json, identifies cohort and sector peers, applies the four guardrails, loads peer content into the working context BEFORE opening any procedure. This happens before Phase 0.5 back-brief.

Mode mapping for batching. Inside the batch pipeline, the orchestrator pre-loads cohort and sector peers per stock at Layer 4 Phase A fire-time. Outside batching (Watson asked to author a memo manually), the same rule fires.
