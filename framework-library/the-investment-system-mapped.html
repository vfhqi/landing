Why this exists

Richard asked one question: "Explain the investment case framework so I understand how you think about it, and can assess how aligned we are."

That question is not really a request for an explanation. It is a fidelity check. Richard has built a large body of investing doctrine into the COWORK folder over five months. A machine now reads that doctrine and produces analysis from it. If the machine's model of the system has drifted from Richard's own, then every memo, every rating and every park decision drifts with it, quietly and at scale.

So the real purpose is: read the codified system back to Richard accurately enough that he can spot where it is wrong.

What this session set out to do

Three things, in order.

  1. Explain the investment case framework — what it is, how it decomposes, and how Watson holds it in mind when analysing a stock
  2. Explain the concept ladder — what is meant by investment philosophy, system, strategy, approach, process and framework, where each is written down, and how they nest
  3. Explain the linkage — how those concepts connect to the Investment Analyst role and to the Analysis and Judgement memos, and where they do not connect

My current reading of the shape

This is the part to attack. It is Watson's inference from a first pass, not established fact.

How to read that stack. Each layer answers a different question, and each one constrains the layer below it. The perpetual goals say what winning looks like. The philosophy says what kind of thing tends to win. The strategy says which specific things to go after. The case framework says what a finished argument for one of those things has to contain. The process says how you build that argument in stages. The roles say who does which part. The memo is what falls out at the end.

The load-bearing claim, and the one most worth challenging: the case framework is the hinge. Everything above it is belief; everything below it is machinery. If the framework is right, the machinery produces good analysis. If it is wrong, the machinery produces confident, well-formatted, wrong analysis.

The confusions found so far

Richard's instruction was to name confusions clearly, not to fix them today. Six are recorded. Each was found by reading the files this session, not inferred.

1. The word "pillar" carries four different meanings

Where Structure What it organises
The memo architecture Three Pillars Change, Building Blocks, Live-monitoring components
The dashboards and ratings Six Pillars The six top-level ratings for a stock
The strategy document Four Pillars What makes a great investment, setups, predictability, operator quality
The case playbook Four pillars again, different content Foundations, change forces, outputs, case

Why it matters. Four structures share one word. Two people can agree entirely about "the pillars" and mean different things.

Richard's ruling, 19-Aug-26. The six-rating framework is to be renamed the Six Master Ratings of Capital Deployment Worthiness, because that name says without ambiguity what the thing is for. The rename is agreed in principle and scheduled, not yet executed.

2. The link between the frameworks is one line long

Only one connection between the three-pillar memo architecture and the six ratings is written down anywhere: the memo's third rating is the same thing as the second of the six ratings, locked 09-Jul-26. Three of the six ratings have no written mapping at all to the memo architecture.

3. Five framework gaps have been open since 30-Jul-26

The question bank states of itself that it is not complete. Three elements carry unanswered placeholders, one element's ten invalidation thresholds were never written into it, and one structural split was Watson's editorial decision awaiting Richard's ruling. These are elements the machine grades every week.

4. A possibly stale machinery layer

Two documents describe a set of twenty-six portfolio-manager deliverables per stock per stage, plus a ratings database, as the live machinery. That description dates from 15-Apr-26. The memo system dated 13-May-26 appears to have taken over memo authoring. Whether the older machinery is retired, running in parallel, or folded in is not recorded anywhere Watson has found. This is flagged for verification, not asserted.

5. A document that contradicts itself in its first two lines

The process document is titled "5-Stage Research Funnel" and its overview paragraph immediately below begins "Four stages". The renumbering note at the top explains why: it was renumbered on 29-Jul-26 and the overview line was not updated with it.

6. Numbers that differ between files

Portfolio size appears as twelve to twenty, sixteen fixed, eight to ten core, and five to fifteen. Minimum daily liquidity appears as five million dollars in two files and ten million in two others. Minimum company size appears as one and a half billion of market value in one place and a five billion sweet-spot floor in another. Individually minor. In aggregate, a screen built from the wrong file returns a different universe.

What we decided today

# Decision Reasoning
D1 The investment case framework means the memo architecture: three Pillars, Elements E1 to E32. Not the six ratings Richard's ruling. He holds a reason he will explain at the appropriate point
D2 Mirror the doctrine first, critique second, fix nothing today Richard cannot assess alignment against a picture Watson has already tidied
D3 Explain at a high to medium level first, going deeper by conversation Avoids tunnelling into one part of a large system too early
D4 The six-rating framework is renamed the Six Master Ratings of Capital Deployment Worthiness, in due course The old name is ambiguous against the other three uses of "pillar"
D5 Build the reading library before the analysis Richard reads source material while Watson works. Removes a serial dependency
D6 Every document Watson reads is disclosed, with a full reading list at the end of the write-up Alignment is impossible if the evidence base is hidden
D7 Portfolio and position management are published but excluded from the analysis Real material, different subject. Reading it does not require analysing it today
D8 Landing-page boxes carry plain-English names; internal filenames appear only in small print Richard, verbatim: the existing filenames are "incredibly confusing"
D9 Watson decides execution questions alone from this point Richard: involve him only on strategic, goal or outcome decisions, or on execution that is material, risky, costly or complex

What we considered and rejected

Recorded so a later session does not re-propose them.

  • Explaining the six-rating framework as a sibling of the memo architecture. Rejected by Richard. It appears only in the confusions section
  • Fixing the pillar-naming ambiguity today. Rejected as too distracting from the core goal. Noted for a future session
  • A single hub box on the landing page opening a library index. Tidier, fewer boxes, but puts the documents one extra click further away. Rejected in favour of one box per document
  • Element-by-element explanation in the main write-up. Roughly fifteen thousand words. Rejected: that is a reference document, not an explanation
  • Watson's own inferred mapping between the two frameworks. Watson formed a hypothesis on a first pass. Deliberately not published as doctrine, because an inference presented as a fact is exactly the failure this session exists to catch
  • Including the writing and presentation standards in the library. Excluded as out of subject
  • Extending the existing framework-visualisation project rather than opening a new one. Rejected by Richard in favour of a new project

Risks carried into the next pass

  • Manufactured coherence. The strongest temptation is to present a tidy unified framework that is partly Watson's own tidying-up. That would look like alignment and be misalignment. Every claim in version 2 must name the file it came from
  • Recency bias. The newest file is not automatically the live one. Confusion 4 above is exactly this risk
  • Watson auditing its own model using its own reading. A deliberately hostile pass is required before version 2, not optional
  • Volume. A faithful explanation could run long enough to be unreadable. Compression is where fidelity dies, so the answer is layering, not cutting
